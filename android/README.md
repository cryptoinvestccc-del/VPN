# Сборка APK без Android SDK от Google

`dl.google.com` в этой среде закрыт прокси, поэтому обычный путь —
Android Studio или `sdkmanager` — недоступен. Приложение всё равно
собирается: всё нужное нашлось в других местах.

| Что | Откуда | Заменяет |
|---|---|---|
| `aapt2`, `apksigner`, `zipalign` | пакет Ubuntu `android-sdk-build-tools` | build-tools из SDK |
| `android.jar` (API 34) | зеркало `Sable/android-platforms` на GitHub | platforms из SDK |
| дексер | `com.jakewharton.android.repackaged:dalvik-dx` с Maven Central | `d8` из SDK |
| движок туннеля | `github.com/amnezia-vpn/amneziawg-go` через прокси модулей Go | NDK |

## Что это накладывает

**Уровень языка — Java 8.** Дексер не принимает классы новее 52-й версии
формата. Для Android это норма, но лямбды и `var` использовать нельзя.

**Ни AndroidX, ни Compose.** Они живут на `maven.google.com`, который
редиректит на закрытый `dl.google.com`. Интерфейс написан на голом
фреймворке: `Activity`, `View`, `Canvas`, `RenderEffect`. Минус —
писать больше. Плюс — **ноль зависимостей** и APK в десятки килобайт
вместо единиц мегабайт, что для этого проекта скорее по духу.

**Минимальная версия — Android 8 (API 26), не 12.** Раньше здесь стояло
31 ради `RenderEffect`, но в сборке его нет: стекло нарисовано
градиентами на Canvas, и ничего из этого не требует Android 12. Если
живое размытие фона когда-нибудь понадобится, его надо запрашивать за
проверкой версии, а не поднимать этот порог.

**Движок туннеля — отдельный статический бинарник**, а не `.so` через
JNI: NDK нет. Go собирает `linux/arm64` без CGO, Android это Linux, и
такой бинарник кладётся в APK как `lib/arm64-v8a/libawg.so`. Android
распаковывает содержимое `lib/` в каталог, откуда исполнение разрешено —
в отличие от каталога данных приложения, где оно запрещено с API 29.
Файловый дескриптор туннеля от `VpnService.establish()` передаётся ему
через `WG_TUN_FD`, как это делает сам wireguard-go.

## Куда приложение обращается

Адрес сервиса выдачи конфигов лежит в `app/res/values/strings.xml`,
строка `provision_endpoint`. Замените на свой до сборки: значение по
умолчанию заведомо нерабочее.

## Использование

```sh
./android/toolchain.sh      # один раз: скачать android.jar и дексер
./android/build.sh          # собрать и подписать APK
```

`toolchain.sh` ничего не берёт с серверов Google и проверяет контрольные
суммы того, что скачал.

## Что проверено, а что нет

**Проверено здесь:** конвейер целиком — ресурсы, компиляция, дексинг,
упаковка, выравнивание, подпись; `apksigner verify` проходит,
`aapt dump badging` читает манифест. Движок AmneziaWG компилируется под
arm64.

**Проверено:** генерация ключей — длина 32 байта, клампинг X25519
верный, каждый вызов даёт новый ключ; оба бинарника движка собираются и
различаются по архитектуре; все классы попадают в dex; подпись проходит
`apksigner verify`.

**Не проверено здесь и проверить нечем:** запуск на настоящем телефоне.
В этой среде нет ни ARM, ни эмулятора, ни устройства. Три места, где
первый запуск покажет то, чего не показывает сборка:

1. **Передача дескриптора.** `VpnService.establish()` возвращает
   дескриптор, у которого выставлен close-on-exec; мы его снимаем через
   `Os.fcntlInt`, но переживёт ли он `exec` именно в реализации
   `ProcessBuilder` на Android — проверяется только на устройстве.
2. **Запуск бинарника из `nativeLibraryDir`.** Должен работать при
   `extractNativeLibs="true"`, но производители иногда ужесточают
   политику.
3. **Тип foreground-сервиса.** `systemExempted` появился в API 34; на
   Android 11 он просто игнорируется, а вот на новых телефонах поведение
   нужно проверять отдельно.
