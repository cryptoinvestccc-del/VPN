# СБОРКА — GitHub Actions, не на ПК
exe собирает `.github/workflows/build-cnc-filler.yml` (корень репозитория, windows-latest, working-directory: cnc-filler) на каждый пуш в `cnc-filler/**`:
установка → `build_db.py` → `pytest tests` → `tools/check_cnc1_live.py` (живой cnc1.ru: карточка MCKNL2020K12 и поиск по 00059015;
HTML — artifact `cnc1-live-html`; падает, если parse_card не достал код 00059015, бренд Sant и «e, мм» = 28) →
`tests/test_cnc1_real.py` → pyinstaller → пробный запуск exe → `tools/secret_scan.py` по исходникам и exe → artifact `cnc-filler-exe`.
Репозиторий публичный: `data/samples/` и `examples_output/` (выгрузки Битрикса/1С) — только локально, в .gitignore; тест на выгрузке SNR/SNL без файла пропускается.
Локально: `python -m venv .venv`, `pip install -r requirements.txt pytest`, `python src/cncfiller/build_db.py`, `python -m pytest tests`.
PDF-каталогов может не быть — это нормально, программа работает на разобранной базе; PDF нужны только для разбора новых страниц.

# Заполнитель свойств CNC

Windows-программа (Python + PySide6 + SQLite) для магазина металлорежущего инструмента cnc1.ru (1С + Битрикс).
На вход: один артикул или Excel-выгрузка из Битрикса/1С. На выход: Excel в формате выгрузки Битрикса с заполненными свойствами из каталогов поставщиков.
Проект согласован с пользователем (Влад) по документу `docs/design.html` — структура БД, окно, правила. Сейчас этап: **MVP написан** (src/cncfiller: build_db.py, articles.py, engine.py, app.py; tests/). Дальше — наполнение базы (Этап 2) и шаблоны других групп.

## Жёсткие правила заполнения (от пользователя, не нарушать)
1. **«Бери значения либо из артикула, либо из каталога — не выдумывай».** Никаких значений по аналогии/соседним размерам. Нет в каталоге → лист «Не найдено» с причиной.
2. **Заполнять только пустые ячейки.** Существующие значения 1С не менять; расхождения с каталогом — на отдельный лист «Расходится с каталогом».
3. **В файле загрузки не должно быть пустых ячеек** в включённых колонках (пустая ячейка стирает значение в 1С). Колонки, которые не заполняем, в файл не включать.
4. **Код товара** (`_Код товара`) — текстом, 8 знаков с ведущими нулями (`str(code).strip().zfill(8)`), number_format '@'.
5. Значения справочных полей — **только из справочников 1С** (`data/dicts/1c_dictionaries.json`). Кермет = «Металлокерамическая»; HRC10 покрытие «Без покрытия (кермет)»; HR115C «PVD (Металлокерамическое покрытие)».
6. `_SEO_Sort` при запросе — шаг 10 (10, 20, 30…), сортировка по указанному полю (обычно L, затем Dmin, затем артикул).
7. Цвета в выходном Excel: жёлтый FFF2A8 — заполнено (было пусто), голубой D9E8FB/BDD7EE — изменено (только SEO_Sort или по явному запросу).
8. Каждое значение — с источником (каталог + страница каталога/PDF) на листе «Источники».

## Знания о каталогах
- Описание всех 18 каталогов и страниц — `docs/catalogs.md`. Поисковый OCR-индекс по страницам — `data/index/idx_<КОД>.json` (ключ = страница PDF).
- Сами PDF не в репозитории (сотни МБ) — пользователь кладёт их в `catalogs/` (список имён файлов в `docs/catalogs.md`).
- Почти все каталоги — **сканы**: цифры из OCR ненадёжны. Таблицы извлекать так: отрендерить страницу (`pdftoppm -r 200`), прочитать картинку, сверить. Сверенные данные — `data/seed/verified_params.csv`, `data/seed/inserts_grades.json`.
- MetalCraft = каталог kkdaoku (Wenling Youyi, индекс UNKNOWN112). Youyiqie — тот же производитель, цифры совпадают; у Youyiqie есть S50U.
- Hadsto: сплавы HS*, стружколом MP; в 1С бренд для этих позиций всё равно **Huareal**.
- На сайте у MetalCraft часть резцов заполнена значениями Sant (не каталожными) — не трогать, только репортить.

## Сопоставление каталог → колонки сайта (проверено на практике)
- Расточные (MetalCraft/kkdaoku): f→S, L1→e, H→H, Dmin→«Dmin» и «Мин. диаметр растачивания», d→«Сечение резца» как «Ø{d}», L→«L» и «Длина резца».
- PTHK (твердосплавные оправки C/E/H): колонки D, L, A, Dmin; **S = A − d/2**; e и H в каталоге нет.
- Резьбовые SN (kkdaoku стр.117): Dmin→Dmin+Мин.диаметр, Φd→d+Диаметр хвостовика+b+Сечение, L→L+Длина резца, H→H+h, F→S, L1→L1; пластина «{size}IR..»/«{size}IL..».
- ISO буква длины державки: F80 G90 H100 J110 K125 L140 M150 N160 P170 Q180 R200 S250 T300 U350 V400.
- Пластины ISO 1832: 02=2.38, T3=3.97 толщина; отверстие 2.8 (IC 6.35) / 4.4 (IC 9.525); радиус 02=0.2 и т.д.
- Сверла YG10 (MetalCraft): серия-константы в `data/samples/bitrix_drills_iblock_element_admin.xls`; L/L2 каталога нет.

## Требования безопасности (от пользователя, проверять перед каждым коммитом/выпуском)
1. Никаких секретов в коде, репозитории и собранном .exe (ключи, токены, пароли). Перед коммитом и выпуском — поиск по изменениям, истории git и артефакту.
2. Хранилища данных закрыты по умолчанию (для нас: БД локальная, без сервера; если появится сервер — RLS/права на сервере).
3. Проверка владельца по id на каждом запросе (если появится серверная часть) + тест с чужим id.
В отчёте о работе указывать, как проверен каждый пункт.

## План
- Этап 1 (MVP): `db/schema.sql` → скрипт `src/cncfiller/build_db.py` загружает seed + индекс; движок поиска/расшифровки; экспорт Excel по шаблонам «Резцы расточные» и «Резцы резьбовые» (образцы в `data/samples/`); окно PySide6 по макету `docs/design.html`; сборка .exe через GitHub Actions (`.github/workflows/build-cnc-filler.yml` в корне репозитория).
- Этап 2: все токарные державки (MetalCraft, Youyiqie, SANT, PTHK) — разбор страниц в seed.
- Этап 3: пластины (Huareal, Hadsto, ZZJG, SANT). Этап 4: свёрла, фрезы, оснастка.
- Нужно от пользователя: по выгрузке Битрикса на каждую группу, справочники 1С по списочным полям.
- Старые рабочие скрипты (логика, которую переносить в движок) — `legacy_scripts/`; примеры готовых файлов загрузки — `examples_output/`.

## Парсер cnc1.ru (src/cncfiller/cnc1_parser.py)
- Поиск по **артикулу**: индекс URL из карты сайта (sitemap.xml → sitemap-iblock-536.partN.xml), артикул совпадает с началом слага URL (s12m_sckcr06_… = S12M-SCKCR06). Дубли с разными кодами возвращаются все. Кэш: data/cnc1_urls.json.
- Поиск по **коду товара** (5–8 цифр): кэш кодов data/cnc1_codes.json → поиск сайта `/catalog/?q=<код>` → по согласию пользователя полный обход карточек (1 запрос/сек), коды копятся в кэш. Карточка принимается, только если «Код товара» на ней совпадает.
  Проверено 22.10.2026: `/catalog/?q=00059015` находит карточку, `?q=59015` и `/search/?q=` — нет, поэтому код ищется сначала полностью (8 знаков), потом без нулей. Ссылки меню отсекаются сравнением с пустым поиском.
- Карточка: H1 (первое слово = артикул), «Код товара» (ищется после H1), характеристики (Aspro Max: properties__title/value — краткий список, props_list char_name/char_value — полный). «-» = пусто. Подсказки hint/tooltip в названиях свойств пропускаются.
- На сайте у одного артикула бывает несколько карточек: MCKNL2020K12 → 00059015 (Sant) и …_tx_… 00115826.
- Живая проверка — шаг workflow (`tools/check_cnc1_live.py`), реальная карточка — `tests/fixtures/cnc1_card.html` + `tests/test_cnc1_real.py`.
- В exe кэши cnc1 лежат в %LOCALAPPDATA%\cnc-filler (папка распаковки exe временная).
- В окне: кнопка «Взять с cnc1.ru» — по полю (несколько через запятую) или по колонке _Код товара/Артикул загруженного Excel; результат становится входной таблицей для «Заполнить».
- Только чтение, без авторизации, не чаще 1 запроса в секунду.
