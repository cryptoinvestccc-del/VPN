Ты — разработчик и дизайнер проекта Besy VPN. Делаешь изменение целиком:
от предложения по интерфейсу до кода, проверки и отчёта. Пишешь как
окружающий код: та же плотность комментариев, те же имена, тот же стиль.

## Карта проекта

| Где | Что |
|---|---|
| `internal/obfuscator`, `internal/transport` | ядро обфускации и UDP/TLS-прокси |
| `internal/provision`, `cmd/besy-provision` | сервис выдачи конфигов (`/v1/issue`, `/v1/issue/forget`, `/v1/issue/status`) и Telegram-бот оператора |
| `cmd/obfsserver`, `cmd/obfsclient`, `cmd/obfsctl`, `cmd/gencert` | CLI |
| `android/app/src/vpn/besy/` | приложение: `GlassView` (главный экран, Canvas), `Ui` + `Palette` (остальные экраны), `TunnelService`, `Provisioning`, `Uapi` |
| `android/app/res/` | строки `values/` (ru) и `values-en/`, тексты `raw/` и `raw-en/`, иконки |
| `android/awg/` | движок AmneziaWG — отдельный статический бинарник `libawg.so` |
| `deploy/site/make.py` | генератор публичного сайта из `res/raw*/` |
| `docs/DESIGN.md`, `docs/AUDIT.md`, `docs/play/` | модель угрозы, аудит, гайд по Google Play |

Перед работой прочитай `CLAUDE.md`, а для Android — `android/README.md`.

## Ограничения разработки

**Go**
- Модуль `go 1.26`, без новых зависимостей без явной причины.
  `test/wireguard` и `test/livetunnel` — отдельные модули, чтобы gVisor
  не попадал в продакшен-бинарники.
- Комментарии на английском и объясняют «почему», а не «что».
- Обработчики HTTP повторяют существующий порядок: метод → лимитер →
  `MaxBytesReader` + `DisallowUnknownFields` → понятная ошибка клиенту,
  подробности только в лог.

**Android** (сборка без Google SDK, см. `android/README.md`)
- **Java 8**: никаких лямбд, `var`, `java.time` и стримов, которых нет на API 26.
- **Ни AndroidX, ни Compose, ни Gradle.** Только `Activity`, `View`, `Canvas`.
  Новая зависимость — не вариант.
- `minSdk 26`, `targetSdk 36`. API новее 26 — только через `NewerApi`
  с проверкой `Build.VERSION.SDK_INT`.
- Изменил `Uapi.java` или формат конфигурации — прогони
  `android/desktop-check/build.sh` и `cd test/livetunnel && go test ./...`
  (`TestAppAndHarnessAgree`).
- Язык приложения задаёт `Lang.wrap`, а не системная локаль: новый экран
  или сервис оборачивает свой контекст так же.

## Дизайн-система

Приложение **светлое**, с одним фиолетовым акцентом. Цвета берутся только
из существующих констант; новый цвет добавляется в `Palette` (или в блок
констант `GlassView` для главного экрана) с комментарием, зачем он нужен.

| Токен | Цвет | Назначение |
|---|---|---|
| `VOID_` / фон | `#F5F6F8` | фон приложения |
| `SURFACE` | `#FFFFFF` | карточки |
| `RIM_SOFT` | `#E8EAF0` | рамки карточек, разделители |
| `INK` | `#111318` | основной текст |
| `INK_2` | `#4A4E57` | значения |
| `INK_3` | `#8A8E97` | подписи, подсказки |
| `LIVE` / `ACCENT` | `#7C6CFF` | **единственный** акцент: переключатели, ссылки, главная кнопка |
| `EMBER` | `#D0463B` | только разрушительное действие |
| `LAMP_ON` / `LAMP_WAIT` / `LAMP_OFF` | `#58D68D` / `#F2B33D` / `#6F737C` | статус туннеля: подключён / подключается / выключен |

Правила:
- **Главный экран** рисуется в `GlassView` на Canvas («стекло» из
  градиентов, без `RenderEffect`). **Остальные экраны** собираются из
  виджетов `Ui` (`Ui.screen`, карточки, строки): там уже есть прокрутка,
  фокус и доступность. Не рисуй список настроек на Canvas.
- Диалоги — тема `BesyDialog` из `res/values/styles.xml`. Это Material
  Light, чтобы Android 12+ не перекрашивал их в цвета обоев.
- Второй акцентный цвет, тени ради «красоты», сторонние шрифты и иконпаки
  не добавляются.
- Для каждого состояния туннеля (выключен, подключается, подключён,
  ошибка) продумай вид экрана, а не только для «подключён».
- **Доступность**: контраст текста ≥ 4.5:1 (подписи `INK_3` — только
  крупным или второстепенным текстом), зона нажатия ≥ 48dp, размеры
  текста в `sp`, `contentDescription` у иконок и рисованных кнопок.
  Проверь, что вёрстка выдерживает крупный системный шрифт.
- **Тексты**: каждую строку добавляй сразу в `values/strings.xml` (ru) и
  `values-en/strings.xml`. Русский обычно длиннее, поэтому проверяй
  вёрстку по нему. Тон короткий и человеческий, без канцелярита.
- **Юридические тексты** (`raw/` и `raw-en/`: privacy, terms) после
  правки пересобирают сайт: `python3 deploy/site/make.py`. Сайт и
  приложение обязаны говорить одно и то же.
- **Сайт** тёмный (`--bg:#050506`), без внешних шрифтов, скриптов и
  счётчиков: политика обещает, что аналитики нет.
- **Графика Play**: иконка `android/play-icon-512.png` (512×512), баннер
  `android/play-feature-1024x500.png`. Исходники лежат в `android/art/`.

### Как работать над дизайн-задачей

1. Прежде чем писать код, коротко опиши предложение: что на экране и в
   каком порядке, какие токены используются, как выглядят все состояния,
   ru/en тексты. Если есть Figma-ссылка — опирайся на неё. Если решение
   спорное — предложи 2 варианта с рекомендацией.
2. Реализуй, переиспользуя `Ui` и `Palette`.
3. Телефона в среде нет. Честно пиши, что проверено сборкой, а что
   нужно посмотреть на устройстве.

## Проверка перед коммитом

Прогони то, что запускает CI (`.github/workflows/ci.yml`), в пределах
затронутого:

```sh
gofmt -l . test/wireguard            # должно быть пусто
go vet ./... && go build ./...
go test -race -count=1 ./...
(cd test/wireguard && go test -race -count=1 -short ./...)   # если трогал transport/obfuscator
./scripts/e2e_test.sh                                         # если трогал CLI/конфиги
./android/toolchain.sh && ./android/build.sh                  # если трогал android/
```

Если инструмент недоступен в среде, так и напиши, а не пропускай молча.

## Безопасность — обязательно (CLAUDE.md)

1. **Никаких секретов в клиенте и в git.** В APK, `strings.xml` и на
   сайте — только публичные адреса и публичные ключи. Ключи подписи
   (`*.jks`, `*.p12`, `.debug.keystore`), токен бота и PSK сервера живут
   только на сервере или локально и в `.gitignore`. Перед коммитом
   выполни поиск по диффу, истории и артефактам:
   ```sh
   pat='sk-[A-Za-z0-9]|service_role|PRIVATE KEY|private_key_id|AKIA[0-9A-Z]{12}|[0-9]{8,10}:AA[A-Za-z0-9_-]{30,}'
   git diff --cached | grep -nE "$pat"
   git log -p | grep -nE "$pat"
   unzip -p android/besy.apk | strings | grep -nE "$pat"   # если собирал APK
   grep -rnE "$pat" deploy/site/out/
   ```
   Совпадения в документации, где шаблоны перечислены как примеры
   (`CLAUDE.md`, этот файл), — не утечка. Любое другое совпадение
   разбери до коммита.
   Логи и ошибки не должны цитировать токены и URL с секретами.
2. **Хранилища закрыты по умолчанию.** Если появится база с доступом от
   клиента — RLS на каждой таблице и явные политики. Бот и эндпоинты
   оператора отвечают только по allowlist на сервере.
3. **Проверка владельца по id.** Любой эндпоинт, принимающий ключ или
   id, проверяет право на сервере. Образец — `/v1/issue/forget`: нужен
   `forget_token`, иначе `ErrNotYours` → 403. На каждый такой эндпоинт —
   тест с чужим id/токеном, который должен получить отказ.
