# Axiomantic — сайт студии

Сайт студии Axiomantic (axiomantic.ru): сайты для бизнеса под ключ.
Дизайн и вёрстка — дизайнера студии (Tailwind); здесь они переведены на
генератор, чтобы каждый текст, цена, кейс, пост и картинка правились в
панели без программиста. Рядом — сервер, который принимает заявки,
комментарии блога и обслуживает панель (её же студия отдаёт клиентам).

```
axiomantic/
  content.py     — все тексты: главная, услуги, кейсы, блог, контакты, документы, SEO
  build.py       — собирает страницы из content.py в site/ (вёрстка дизайнера)
  cms/schema.json — разделы панели: какие поля, типы, длины
  site/          — готовый сайт (HTML генерируется, assets/ — руками, кроме отмеченных ниже)
    assets/css/main.css        — Tailwind, собранный из классов build.py (tailwind/)
    assets/css/*.css           — подвал, окно заявки, страницы документов, схема на главной
    assets/js/main.js          — меню, окно «Обсудить проект», формы, cookie и Метрика
    assets/js/blog.js          — рубрики, лайки и комментарии блога
    assets/js/process-flow.js  — анимация схемы «Как мы решаем задачи»
    assets/fonts/              — Inter (OFL), без Google Fonts
    assets/vendor/fontawesome/ — иконки Font Awesome Free, свои копии
  tailwind/      — сборка main.css (нужна, только когда меняется вёрстка build.py)
  leads/         — сервер заявок, блога и панель (Go, без зависимостей)
    admin/                     — страницы панели, встроены в бинарник
  deploy/        — nginx и unit systemd для axiomantic.ru
```

Часть файлов в `site/assets/` пишут скрипты, и правка руками в них
пропадёт (а CI упадёт на `git diff`): `favicon.svg` и `css/site.css`
пишет `build.py`, `css/main.css` — сборка Tailwind.

Посмотреть локально:

```bash
python3 axiomantic/build.py                       # пересобрать страницы
python3 -m http.server -d axiomantic/site 8000     # открыть http://localhost:8000
```

Формы, комментарии и панель работают через сервер (раздел 10, «Попробовать у себя»).

---

## 1. Страницы

| Адрес | Что на ней |
|---|---|
| `/` | первый экран, для кого, схема «Как мы решаем задачи», продуктовый подход, услуги, кейсы, тарифы, баннер, форма |
| `/services/` | список услуг и баннер |
| `/portfolio/` | все кейсы |
| `/cases/<ключ>/` | кейс: факты, боль и решение, галерея экранов, мобильная версия, функционал, результаты |
| `/blog/` | посты команды с рубриками, лайками и комментариями (после модерации) |
| `/contacts/` | контакты и форма, команда, частые вопросы |
| `/privacy/`, `/consent/` | политика и согласие на обработку персональных данных |
| `/about/`, `/<ключ>/` | «О студии» и посадочные страницы — когда включены в панели |
| `/404/` | ответ nginx на любой несуществующий адрес |

Старые адреса вёрстки (`services.html`, `case-auto.html`) nginx
переадресует на новые. Есть `sitemap.xml`, `robots.txt`, canonical,
Open Graph и разметка Schema.org (организация, хлебные крошки, FAQ).

## 2. Как устроено

`build.py` повторяет разметку дизайнера класс в класс; сравнение
страниц со страницами из архива дизайнера: та же высота на 1440 и 390 px,
отличаются меньше 0,5% точек (даты в блоге, логотип Max). Все тексты —
из `content.py` или черновика панели; в текстах работают `**жирный**` и
`[ссылки](privacy/)`.

Цвета, скругления и ширина — CSS-переменные (`tailwind/input.css`), так
что «Дизайн» в панели меняет их без пересборки Tailwind: `build.py`
пишет переопределения в `css/site.css`. Классы Tailwind берутся из
`build.py`: если в шаблон добавлен новый класс, пересоберите стили:

```bash
cd axiomantic/tailwind && npm ci && npm run build
```

Ничего не грузится со сторонних серверов: шрифт и иконки свои. Яндекс
Метрика — только когда номер счётчика задан в панели и посетитель нажал
«Принять» в уведомлении о cookie. Под строгой CSP из `deploy/snippet-axm-site.conf`
сайт проверен без нарушений.

## 3. Формы и блог

Формы (главная, контакты, окно «Обсудить проект») отправляют заявку на
`/api/lead`: имя, телефон или ник в Telegram (или почта), задача,
тариф, если окно открыто кнопкой тарифа. Проверка — на сервере, те же
правила в браузере. Скрытое поле ловит ботов.

Блог: лайки и дизлайки — счётчики на сервере (`/api/blog/react`); один
голос с адреса, забрать его может только тот же адрес. Комментарии
анонимные (`/api/blog/comments`), появляются после одобрения в панели
(«Комментарии»). Ни имён, ни адресов посетителей сервер не хранит:
лимиты и память о голосах — только в оперативной памяти. Комментарии
выводятся как текст, ссылки не кликабельны.

## 4. Как менять сайт

На сервере — в панели (раздел 10). В репозитории: правка `content.py`,
затем `python3 axiomantic/build.py` и коммит вместе с `site/`. Когда в
панели уже есть черновик, правка `content.py` на сервере на сайт не
влияет (новые блоки, появившиеся в `content.py`, панель добавит в
черновик сама).

## 9. Приём заявок

`leads/` — сервис на Go без внешних зависимостей. Он принимает
`POST /api/lead` и проверяет форму по тем же правилам, что и страница
(российский номер — ровно 11 цифр). Каждую заявку он дописывает в файл
(JSON Lines, права `600`). Если задан бот, копия уходит в Telegram-чат.
Публичный адрес только принимает: прочитать заявку обратно через него
нельзя. Читают заявки в панели (раздел 10) — только после входа и
только своего рабочего пространства.

Защита: 5 попыток за 10 минут с адреса (IPv6 — с сети /64); потолок в
60 заявок за 10 минут на каждый сайт считает только заявки, которые
реально сохраняются. Мусорные запросы его не выбирают, а поток
правдоподобных заявок закрывает форму только того сайта, на который он
идёт, — не студии и не других клиентов.
Проверка `Origin` (чужой сайт не отправит форму из браузера
посетителя), тело не больше 16 КБ, неизвестные поля отклоняются,
скрытое поле-ловушка для ботов. Уведомление в Telegram — простой текст
без разметки.

Запуск на сервере (Ubuntu/Debian). В `deploy/axm-site.service` и
`deploy/axm-site.conf` уже стоит axiomantic.ru; для другого домена замените
его — с чужим `Origin` сервис отвечает на заявки 403.

```bash
cd axiomantic/leads && CGO_ENABLED=0 go build -trimpath -o axiomantic-leads .
sudo install -m 755 axiomantic-leads /usr/local/bin/
sudo useradd --system --no-create-home --shell /usr/sbin/nologin axmsite
sudo install -d -m 750 -o root -g axmsite /etc/axm-site
sudo install -m 644 ../deploy/axm-site.service /etc/systemd/system/
# Telegram (по желанию): токен вводится в редакторе, а не в командной
# строке — её видят ps, журнал sudo и история shell
sudo install -m 600 -o root -g root /dev/null /etc/axm-site/leads.env
sudoedit /etc/axm-site/leads.env     # AXM_TG_TOKEN=…  и  AXM_TG_CHAT=…
# панель и публикация сайта: см. раздел 10 — без admin.json сервис не стартует
sudo systemctl daemon-reload && sudo systemctl enable --now axm-site
```

nginx: `deploy/snippet-axm-site.conf` (общая часть) и `deploy/axm-site.conf`; установка рядом со старым сайтом — `deploy/INSTALL.md`. Заявки лежат в
`/var/lib/axm-site/leads.jsonl`. Удалить данные одного человека по его
запросу — кнопка в карточке заявки (раздел 10). Чистить старые записи
по сроку из политики — только с остановленным сервисом:
`systemctl stop axm-site`, правка файла, `systemctl start`.
Заявка, пришедшая во время правки на ходу, может потеряться, а панель
увидит изменения только после перезапуска.

## 10. Панель управления сайтом (админка)

Панель, в которой меняют сайт без программиста: тексты, цены, кейсы,
статьи, контакты, картинки. Заявки — отдельный модуль той же панели.
Это и рабочий инструмент студии, и продукт, который студия отдаёт
клиенту вместе с сайтом. Открывается на том же домене по адресу
`/admin/`, вход — по логину и паролю. Визуальный язык взят из референса
(SaaS-дашборд Roomify на Behance): белая боковая панель, лавандовая
дымка, чёрные и синие карточки. Тексты, картинки и логотип референса не
использованы.

**Что умеет**

- **Всё содержимое сайта** — 30 разделов:
  - «Главная»: первый экран, проблемы клиента, для кого, этапы работы,
    продуктовый подход, услуги, сравнение с обычной разработкой, кейсы
    на главной, тарифы и цены, условия работы, баннер, форма заявки;
  - «Страницы»: услуги, портфолио, кейсы (карточка, страница, экраны,
    результаты), блог (рубрики и посты), страница контактов (команда,
    вопросы), «О студии», посадочные страницы под запросы (`/ключ/`),
    политика, согласие, страница 404;
  - «Настройки»: контакты, меню и реквизиты, форма заявки и окно,
    подписи кейсов и блога, заголовки страниц для поиска, настройки
    поиска (индексация, коды Яндекса и Google, картинка для ссылок,
    фавикон), дизайн (цвета, скругления, ширина), политика и cookie,
    подключения (Яндекс Метрика, Вебвизор).

  У генератора нет своих текстов: каждый заголовок, кнопка и подпись
  берутся из админки. Блоки, которых нет в макете (проблемы клиента,
  сравнение, условия, «О студии», посадочные), выключены, пока их не
  включат.
- **Комментарии блога**: очередь на проверку, «Опубликовать», «Скрыть»,
  «Удалить».
- **Картинки**: обложки и экраны кейсов, картинки постов и страниц, логотип;
  пока картинки нет, на сайте заглушка из макета. Фавикон загружается квадратом, сервер делает PNG 32, 180 и
  512 px.
- **Медиатека**: все загрузки, где каждая стоит; удаляется только
  картинка, которая нигде не используется (ни в черновике, ни в копиях
  сайта). В любом поле картинки — «Из медиатеки».
- **Черновик → предпросмотр → публикация.** «Сохранить» (Ctrl/⌘+S)
  пишет в черновик. «Предпросмотр» собирает сайт и открывает его в новой
  вкладке (только для вошедших, формы не отправляются). Перед публикацией
  видно, что изменится: поле за полем, «было → стало». Публиковать можно
  сразу или в заданное время. Сайт переключается одним действием. Если
  двое правят один раздел, второй получит «раздел изменили — обновите».
- **Резервные копии**: последние 10 публикаций с датой, автором и
  заметкой; владелец возвращает любую одной кнопкой.
- **Журнал действий**: кто и когда сохранил раздел, опубликовал сайт,
  загрузил или удалил картинку, запланировал публикацию.
- **Индексация**: после каждой публикации Яндекс получает список страниц
  по IndexNow; статус и кнопка «Отправить ещё раз» — в «Индексация».
- **Проверка сайта**: ошибки в черновике, итог сборки, недостающие
  картинки, битые ссылки, длинные заголовки, забытая плашка «Демо».
- **Поиск по настройкам и тексту сайта**: строка «Найти настройку…»
  находит раздел по названию, подписи поля или по тексту, который в нём
  написан.
- **Доступ**: пользователи (добавить, роль, отключить, новый пароль —
  показывается один раз), смена своего пароля. Роли: владелец (всё),
  менеджер (правит, публикует, планирует), наблюдатель (только смотрит).
- **Заявки** (если включены): дашборд, список, карточка со статусами и
  заметками, экспорт в CSV, удаление персональных данных по запросу
  человека (ст. 21 152-ФЗ).
- Светлая и тёмная тема, мобильная версия.

**Яндекс Метрика и cookie.** Номер счётчика вводится в «Подключения и
аналитика». На сайте появляется уведомление о cookie; счётчик
загружается только после «Принять» (Метрика ставит cookie, это
персональные данные по 152-ФЗ). Если включаете Метрику, допишите её в
политику обработки данных. В `deploy/snippet-axm-site.conf` CSP уже разрешает
`mc.yandex.ru`; в предпросмотре счётчик не работает.

**Как устроено.** Всё внутри того же сервиса на Go: API `/api/admin/*`
(`leads/admin.go`, редактор — `leads/cms.go`, `leads/media.go`,
пользователи — `leads/users.go`), страницы панели (`leads/admin/`, HTML +
CSS + JS без фреймворков и CDN) встроены в бинарник. Формы разделов
панель рисует по схеме `cms/schema.json`: какие поля, их типы, длины,
обязательность. Сервер проверяет каждое сохранение по той же схеме —
лишнее поле, слишком длинный текст, неверный цвет или адрес, ссылка на
несуществующий кейс отклоняются с понятным сообщением у поля.

Черновик — один JSON-файл. Первый раз он берётся из `content.py`
(`build.py --export-content`); дальше источник правды — черновик, и
правка `content.py` на сервере на сайт уже не влияет. Сборка — тот же
`build.py`, которому черновик передаётся через `AXM_CONTENT`, а папка
выпуска — через `AXM_OUT`; поэтому сайт из панели совпадает с сайтом из
репозитория байт в байт. Выпуски лежат в `<root>/releases/<id>`, nginx
отдаёт `<root>/current` — ссылку на действующий выпуск, которую панель
меняет одним `rename`.

Пользователи и рабочие пространства — `admin.json` (хеши паролей, права
`600`; с более открытыми правами сервис не стартует). Его меняют и
консольные команды, и панель (раздел «Пользователи»), под общей
блокировкой файла. Отключённый сотрудник или новый пароль действуют
через несколько секунд, открытые сессии закрываются.

**Попробовать у себя**

```bash
cd axiomantic/leads
go run . admin workspace set -config /tmp/axm/admin.json -id studio -name "Аксиомантик" \
  -origins http://127.0.0.1:8090 -site http://127.0.0.1:8090 \
  -site-dir "$PWD/.." -site-root /tmp/axm/www -site-data /tmp/axm/site
go run . admin user add -config /tmp/axm/admin.json -workspace studio \
  -login you@studio.example -name "Имя Фамилия" -role owner    # печатает пароль один раз
go run . admin demo -config /tmp/axm/admin.json -store /tmp/axm/leads.jsonl -workspace studio  # демо-заявки
go run . -store /tmp/axm/leads.jsonl -admin /tmp/axm/admin.json
# → http://127.0.0.1:8090/admin/ ; опубликованный сайт — /tmp/axm/www/current
```

`admin demo` заполняет только пустой файл: демо-заявки никогда не
смешиваются с настоящими. Флаг `-admin-ui-dir leads/admin` отдаёт
страницы панели прямо с диска — для работы над интерфейсом без
пересборки.

**На сервере**

```bash
# исходники сайта (читает сервис, пишет только root)
sudo install -d -m 755 /opt/axm-site
sudo rsync -a --delete --exclude leads/ --exclude tailwind/ axiomantic/ /opt/axm-site/   # из корня репозитория
# сюда панель публикует выпуски
sudo install -d -m 755 -o axmsite -g axmsite /var/www/axm-site
sudo install -d -m 700 -o axmsite -g axmsite /var/lib/axm-site
sudo axiomantic-leads admin workspace set -config /var/lib/axm-site/admin.json -id studio \
  -name "Axiomantic" -origins https://axiomantic.ru,https://www.axiomantic.ru \
  -site https://axiomantic.ru \
  -site-dir /opt/axm-site -site-root /var/www/axm-site -site-data /var/lib/axm-site/site
sudo axiomantic-leads admin user add -config /var/lib/axm-site/admin.json -workspace studio \
  -login owner@axiomantic.ru -name "Имя Фамилия" -role owner
sudo chown axmsite:axmsite /var/lib/axm-site/admin.json   # один раз; дальше владелец сохраняется
sudo systemctl restart axm-site
```

Затем войти в `/admin/` и один раз нажать «Опубликовать»: до первого
выпуска `current` нет, и nginx отвечает 404. На сервере нужен
`python3` (только стандартная библиотека).

Пароль никогда не передаётся флагом: он генерируется и печатается один
раз, либо читается из stdin (`-password-stdin`). Остальные команды:
`admin user passwd | disable | enable | remove | list`. В nginx нужны
блоки `location /admin/` и `/api/admin/` из `deploy/snippet-axm-site.conf`; там же
закомментирован пример, как пустить в панель только офис.

**Отдать клиенту.** Панель одна, а сайт у каждого клиента свой: у сайта
должны быть генератор, который читает `AXM_CONTENT` и пишет в `AXM_OUT`,
и своя `schema.json` с разделами этого сайта (`-site-dir` указывает на
папку с `build.py`, `site/` и `cms/schema.json`). Панель рисует формы по
схеме, поэтому код панели под клиента не меняется. Флаг `-no-leads`
прячет заявки, если клиенту нужен только редактор.

Если сайт клиента живёт на сервере студии — добавьте ему рабочее
пространство (`-id client -name "…" -origins https://client.example
-accent '#0F7B6C' -logo К -telegram-chat <id>` и свои `-site-*`) и
пользователей; в server-блоке nginx клиента проксируйте `/api/lead`,
`/admin/` и `/api/admin/` на тот же сервис — с теми же строками, что в
`deploy/snippet-axm-site.conf`: `proxy_set_header Host $host;` и обязательно
`proxy_set_header X-Real-IP $remote_addr;`. Без второй строки адрес
посетителя возьмётся из его же заголовка, и лимиты входа и заявок
перестанут работать. Клиент входит на своём домене и видит только свой
сайт и свои заявки. Если клиенту нужна своя копия — тот же бинарник на
его сервере и свой `admin.json` с одним пространством.

**Безопасность панели**

- Пароли — PBKDF2-SHA256, 600 000 итераций, соль 16 байт. Неизвестный
  логин проверяется так же долго, как неверный пароль; ответ одинаковый.
- Cookie `__Host-axm_admin`: HttpOnly, Secure, SameSite=Strict. Сервер
  хранит только SHA-256 токена. Сессия живёт 12 часов без действий и не
  дольше 7 дней.
- Каждый изменяющий запрос требует CSRF-токен сессии в заголовке и
  проверяет `Origin` / `Sec-Fetch-Site`.
- Вход: 10 попыток за 15 минут с адреса (IPv6 — с сети /64), 5 неудачных
  на пару «логин + адрес» и 20 неудачных на логин с браузеров, которые в
  него ещё не входили. Браузер, из которого человек уже входил, несёт
  cookie устройства, и последний лимит его не держит — подбор пароля с
  тысячи адресов упирается в 20 попыток, а владелец из своего браузера
  входит и во время атаки. Попытки резервируются до проверки пароля, так
  что параллельные запросы лимит не обходят.
- Каждый запрос по id (заявка, пользователь, выпуск, картинка) ищет
  объект только в рабочем пространстве из сессии: чужой id выглядит как
  несуществующий (404). Роли проверяет сервер, не интерфейс.
- Запланированная публикация выполняется от имени того, кто её назначил;
  если к этому времени он отключён или стал наблюдателем, план
  отменяется и это видно в журнале.
- Токен Telegram-бота в админке не хранится и в содержимое сайта не
  попадает — только в окружении сервиса. Ключ IndexNow — публичный по
  своей природе (лежит на сайте файлом), секретом не является.
- Содержимое черновика проверяется по схеме на сервере: управляющие
  символы и символы смены направления текста отклоняются, цвета — только
  `#RRGGBB`, ключи кейсов — только `a-z0-9-`, адреса — по шаблонам.
  Генератор экранирует всё, что пишет в HTML.
- Сборка запускается без переменных окружения сервиса: токен Telegram
  генератору недоступен. Предпросмотр и картинки отдаются только после
  входа, пути с `..` отклоняются.
- Данные посетителей и тексты черновика в интерфейсе выводятся только как
  текст (никакого `innerHTML`). Строгий CSP без inline-скриптов, запрет
  фреймов, `noindex`.
- Экспорт CSV: разделитель «;», все поля в кавычках, формулы
  обезврежены — Excel не выполнит то, что ввёл посетитель.

## 11. Проверки безопасности (CLAUDE.md)

1. **Секретов нет на клиенте и в репозитории.** Секреты — токен
   Telegram-бота и хеши паролей панели. Токен живёт только в
   `/etc/axm-site/leads.env` (root, `600`) и передаётся через
   окружение, не флагами и не в командной строке. Ошибки Telegram не
   цитируют URL запроса, а значит и токен (тест). Генератор сайта
   запускается с пустым окружением и токена не видит. Хеши — в
   `/var/lib/axm-site/admin.json` (`600`), браузер их не получает
   (тест); новый пароль сотрудника показывается один раз и нигде не
   хранится открытым текстом. Пароли не передаются флагами. В `site/` и в
   страницах панели нет ключей; CI ищет шаблоны ключей в собранном сайте
   на каждом пуше.
2. **Хранилище закрыто по умолчанию.** Базы с доступом от клиента нет.
   Файл заявок, `admin.json`, черновик и копии выпусков — права `600`
   в `/var/lib/axm-site`; сервис не стартует, если они лежат внутри
   публикуемой папки (или `admin.json` читают другие). Публичный
   эндпоинт только принимает. Все адреса `/api/admin/*` без сессии
   отвечают 401, без CSRF-токена — 403, без нужной роли — 403;
   предпросмотр и загруженные картинки без сессии недоступны.
3. **Проверка владельца по id.** Каждый запрос с id заявки,
   пользователя, выпуска или картинки ищет объект только в рабочем
   пространстве из сессии; изменение и удаление — только с сессией и
   CSRF-токеном. Тесты с чужим id: `TestSiteRolesAndWorkspaces` (выпуск,
   черновик и список копий чужого сайта), `TestSiteMediaCover` (чужая
   картинка → 404), `TestSiteMediaLibraryAndIcons` (удаление чужой
   картинки → 404, журнал чужого сайта не виден), `TestTeamManagement` (отключить, сбросить пароль,
   удалить чужого пользователя → 404),
   `TestAdminForeignIDIsNotFound` (чтение, смена статуса, заметка,
   назначение, удаление чужой заявки → 404, её данные на месте),
   `TestAdminAssigneeMustBeOwnActiveMember`,
   `TestAdminWorkspacesSeeOnlyTheirLeads`, `TestAdminRoutesNeedASession`,
   `TestAdminWritesNeedCSRF`, `TestAdminRoles`; публичная часть —
   `TestNoRouteByID`.
