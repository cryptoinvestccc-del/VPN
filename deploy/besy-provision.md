# Выдача конфигов для приложения «одна кнопка»

Приложение скачивают, нажимают кнопку — и оно подключено. Никаких
ключей, никакого импорта. Эта служба — то, что делает такое возможным.

## Почему нельзя просто зашить ключ в приложение

Самый очевидный путь — положить один готовый конфиг внутрь APK — не
работает, и не по той причине, о которой думают в первую очередь.

Да, ключ из APK достаётся за минуту: это обычный zip. Но главное не в
этом. В WireGuard пир опознаётся по публичному ключу, и сервер хранит
**один адрес на пир**. Каждое новое рукопожатие перезаписывает
предыдущий. Два телефона с одним ключом будут по очереди выбивать друг
друга, и не будет работать ни у кого.

Общий ключ не «хуже масштабируется». Он ломается на **втором**
пользователе.

## Как устроено вместо этого

1. При первом запуске приложение **само создаёт приватный ключ на
   телефоне**.
2. Шлёт сюда **только публичный**. Приватный не уходит с устройства
   никогда — эта служба его не видит и не может увидеть.
3. Служба выделяет адрес, добавляет пир в AmneziaWG и возвращает всё
   остальное: публичный ключ сервера, адрес, параметры обфускации.
4. Приложение собирает конфиг и подключается.

Для пользователя — те же две секунды. Для вас — возможность отозвать
одно устройство, не трогая остальные.

**Что не собирается.** В запросе одно поле — публичный ключ. Нет полей
для имени, идентификатора устройства или почты, и запрос с лишним полем
отвергается: бесплатный VPN, который собирает такое, — уже что-то
другое. Записи о том, кто спрашивал, не ведётся.

## Установка

Нужен root на сервере Amnezia.

```sh
scp besy-provision-linux-amd64 root@СЕРВЕР:/usr/local/bin/besy-provision
ssh root@СЕРВЕР chmod +x /usr/local/bin/besy-provision
```

Сначала проверка — она ничего не меняет:

```sh
besy-provision -check -endpoint ВАШ_АДРЕС:51820
```

Должно напечатать имя контейнера, интерфейс и число пиров. Если не
находит контейнер — выведет список запущенных, чтобы было видно, что не
так.

Затем служба:

```sh
cat > /etc/systemd/system/besy-provision.service <<'UNIT'
[Unit]
Description=BESY provisioning (issues one AmneziaWG credential per install)
After=docker.service network-online.target
Wants=network-online.target

[Service]
Type=simple
SupplementaryGroups=docker
NoNewPrivileges=true
ProtectSystem=strict
ProtectHome=true
PrivateTmp=true
ExecStart=/usr/local/bin/besy-provision \
    -listen 127.0.0.1:9181 \
    -endpoint ВАШ_АДРЕС:51820 \
    -subnet 10.8.1.0/24 \
    -persist
Restart=always
RestartSec=2s

[Install]
WantedBy=multi-user.target
UNIT
systemctl daemon-reload
systemctl enable --now besy-provision
```

Наружу выставлять только через обратный прокси с TLS. При этом включите
`-trust-forwarded-for`, иначе все запросы будут выглядеть как один
источник и ограничение частоты потеряет смысл. Без прокси этот флаг
**не включать**: заголовок может подделать кто угодно.

## Про `-persist` — прочитать обязательно

`awg set` меняет только то, что работает в памяти. Без сохранения в
конфиг **все выданные доступы исчезнут при первом перезапуске сервера**
— разом и у всех, при этом до перезапуска всё работает безупречно.

Флаг `-persist` запускает `awg-quick save` после каждого изменения. По
умолчанию он **выключен**, и служба громко предупреждает об этом при
старте. Так сделано намеренно: подходит ли `awg-quick save` конкретно
вашей установке Amnezia, отсюда проверить нельзя, а молча писать в
конфиг чужого рабочего сервера — не то, что стоит делать по умолчанию.

Проверьте на своём сервере и включайте.

## Сроки жизни доступов

Это не про экономию места. Рукопожатие сверяется со списком пиров, и
стоимость неаутентифицированного пакета растёт вместе с длиной списка —
та же находка 22 из `docs/AUDIT.md`, только сюда она приходит не от
атакующего, а от обычных людей, которые поставили приложение и забыли.

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `-ttl` | 30 дней | без рукопожатия дольше — доступ отзывается |
| `-grace` | 24 часа | ни разу не использованный доступ живёт столько |
| `-max-peers` | 4000 | потолок; сверх него новым отвечает «сервер заполнен» |
| `-sweep` | 1 час | как часто убирать |

Никого это не наказывает: устройство, которое не подключалось месяц, не
пользуется тем, что у него есть, и получит новый доступ сразу, как
попросит. Освобождённый адрес переиспользуется.

Одна честная оговорка: даты первого появления неиспользованных доступов
живут в памяти, а не на диске. После перезапуска службы такой доступ
проживёт лишним один `-grace`. Это вся цена решения не заводить базу,
которая могла бы разойтись с реальным состоянием интерфейса.

## Ограничение частоты

Эндпоинт доступен любому, кто скачал приложение, — в этом его смысл, но
это же значит, что он доступен и тому, кто захочет забить список пиров.
По умолчанию: три запроса в минуту с адреса, всплеск до десяти. Телефон
провизионится один раз; то, что просит постоянно, — не телефон.

## Проверка руками

```sh
curl -s -X POST http://127.0.0.1:9181/v1/issue \
  -H 'Content-Type: application/json' \
  -d '{"public_key":"'"$(wg genkey | wg pubkey)"'"}' | jq
```

В ответе должны быть `address`, `server_public_key`, `endpoint` и блок
`awg` с параметрами обфускации. Приватного ключа в ответе нет и быть не
может.
